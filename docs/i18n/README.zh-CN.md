> 大多数人脸演示会自信地给你一个数字："开心 87%"。它们不会告诉你，这是从一帧模糊画面、头偏了 30°、台灯侧光下算出来的。
>
> **这个项目给你数字，也给你"别太信它"的理由。** 挑一下眉，你会看到一个带区间的动作估计、一个置信度，以及一道可能把这一帧降权甚至直接暂停的质量关卡。

一个实验性、本地优先的浏览器工作台，面向研究 **FACS 启发的面部动作单元（AU）几何**的开发者。它只报告可观察的面部动作和不确定性——**不输出**身份、意图、情绪、真诚度、性格，也不做任何医学或心理诊断。

## 👋 给人读的部分

### 第一次实验

1. [启动应用](#本地运行与验证)，坐在光线好的地方，用中性表情完成校准。
2. 做一个小而明显的动作：挑眉或张嘴。
3. 同时看三样东西：动作数值、它的区间、质量/置信度指示。

再试试这些对比：

| 试一试 | 观察 | **不要**得出 |
| --- | --- | --- |
| 中性 → 轻微挑眉或张嘴 | 估计值和区间 | 某个数值代表情绪、真诚或意图 |
| 正脸 → 更难的角度或光线 | 质量分、置信度、降权/暂停 | 画面越差越能说明这个人什么 |
| 开始一段短录制 → 导出 | 本地历史、JSON/CSV | 导出结果是诊断或真实世界准确率报告 |

界面有中英文切换、历史和导出。录制永远需要你主动开始；不录制也能观察实时流程。

### 处理流程

1. **关键点**：MediaPipe 提供 468+ 个归一化面部关键点。
2. **质量关卡**：评估关键点完整性、人脸边界/尺度、头部姿态、照度、对比度、过曝、清晰度、眼部可见度/反光代理指标。
3. **通过 / 降权 / 暂停**：暂停帧既不能更新 AU 推断，也不能更新个人校准。
4. **稳健个人基线**：中位数 + MAD，剔除离群帧，只在安静、高质量帧上缓慢且有上限地漂移。
5. **姿态补偿**：头部姿态补偿 + 人脸归一化距离，减少姿态和固定脸型的影响。
6. **AU 估计**：每个 AU 返回 `value`、`lower`、`upper`、`confidence`、`region`。
7. **时间滤波**：显式时长贝叶斯滤波（不是按帧数的迟滞），给出后验置信度和归一化不确定性。
8. **可观察摘要**：眉、眼、颊、鼻、唇、口等 12 项动作摘要，区间随之传播。

**不附带任何学习模型。** 可选 AU 提供者必须在元数据中声明名称、版本、许可证、训练数据来源、AU 标签映射和评估指标才会启用；即便启用，贡献也按质量加权并封顶，确定性几何规则始终是兜底。详见 [ALGORITHM_V3_11.md](../../ALGORITHM_V3_11.md)。

### 本地运行与验证

需要 Node.js/npm、现代浏览器、可用摄像头、`localhost` 或 HTTPS，以及访问 MediaPipe CDN 和网页字体的网络。画面在本地处理，但首次启动不是离线的。

```powershell
npm install
npm run check     # 单元/契约测试、确定性 AU 指标夹具、ESLint、静态发布检查
npm start         # 通过 npx http-server 在 :8080 起静态服务（首次可能下载）
```

**第一次成功**：在实时校准/质量面板里做一个动作，对比估计值和不确定性显示。`npm run check` 通过不能代替这一步摄像头检查。

评估命令（每个 AU 的精确率、召回率、F1、误报率和留出受试者摘要）：

```powershell
node scripts/evaluate-au.mjs evaluation/fixtures/synthetic-au-eval.json
```

> 附带的向量是**合成契约测试**。v3.11 时没有可再分发、合法标注的真人视频数据集，因此**不宣称任何真实视频准确率或跨人泛化能力**。见 [evaluation/README.md](../../evaluation/README.md)。

### 常见问题

**这是情绪识别器吗？** 不是。输出是几何与动作代理量。
**为什么暂停了？** 姿态、可见度、光线等没过质量关卡。改善画面即可；暂停不代表对这个人有任何结论。
**合成评估能证明在我的摄像头上准吗？** 不能，它只验证指标和测试契约。
**历史存在哪？** 开始录制后存在浏览器本地 IndexedDB；导出是本地下载。两者都请当作个人数据对待。

欢迎结果可检验的贡献：质量关卡与校准边界情况、无障碍标签与更清楚的不确定性说明、翻译、AU 几何与时间滤波回归测试、使用合规授权数据的可复现评估工具。在 [PR](https://github.com/son-gladyso/FaceExpressionVFX/pulls) 中写清问题、证据、实际跑过的测试和仍未验证的部分；大改动先开 [issue](https://github.com/son-gladyso/FaceExpressionVFX/issues)。

## 🤖 给 AI 读的部分

**模块地图：**

| 文件 | 职责 | 改动时需补的证据 |
| --- | --- | --- |
| `face-quality.js`、`face-policies.js` | 帧质量关卡、AU 置信区间、策略 | 聚焦回归用例 + 期望的通过/降权/暂停 |
| `face-au-detector.js` | 稳健校准、姿态补偿、确定性 AU 几何 | 确定性输入序列 + 明确输出边界 |
| `face-temporal.js` | 显式时长贝叶斯状态滤波 | 同上 |
| `face-observables.js` | 12 项可观察动作摘要 | 区间传播不丢失 |
| `face-model-adapter.js` | 来源受控的可选提供者 + 规则兜底 | 元数据关卡不可绕过 |
| `face-i18n.js`、`index.html` | 界面文案、语言切换 | 两种语言；保留不确定性表述 |
| `face-history.js`、`face-export.js` | IndexedDB 历史、JSON/CSV 导出 | 录制保持主动、本地 |
| `scripts/evaluate-au.mjs`、`evaluation/` | 固定清单评估 | 合成与真实视频证据分开标注 |

**硬性规则：**

- 不得新增声称情绪、意图、身份、真诚、性格、健康或诊断的输出、标签或文案；用词限定为"可观察动作"。
- 暂停帧不得更新推断或校准；每个 AU 必须保留 `value/lower/upper/confidence/region`。
- 可选模型不得绕过来源/元数据关卡或贡献上限；确定性几何始终兜底。
- 不得上传画面、关键点或历史；录制必须由用户主动开始。
- 不要把合成夹具指标说成真实准确率。
- 未获明确授权，不提交人脸录像、生物特征嵌入、模型权重或数据集。

**验证：** `npm run check`
