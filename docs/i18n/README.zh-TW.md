**查看臉部動作估計，也了解為什麼不應過度相信這些估計。**

FaceExpressionVFX 是實驗性瀏覽器工作台，讓開發者探索受 FACS 啟發的臉部動作單元（AU）幾何特徵。攝影機處理在本機進行；品質門檻、校準及不確定性讓整個流程可供檢視。3.11 版報告可觀察的動作估計及不確定性，不輸出身分、意圖、真實性、真誠程度、人格特徵，也不提供心理或醫學診斷。

<a id="what-you-can-explore"></a>
## 可以探索什麼

臉部動作示範經常只顯示一個數值，卻不說明何時會失去可靠性。本專案將品質檢查與不確定性連同動作估計一起呈現。

- 查看眉毛、眼睛、臉頰、鼻子、嘴唇及嘴部的動作摘要。
- 了解校準、頭部姿態與影格品質如何影響輸出。
- 在加入選用模型之前，先探索確定性規則與測試。
- 只有你主動選擇時才記錄歷史，再匯出為本機下載檔案。

本專案面向希望研究可觀察臉部動作，以及幾何處理流程局限的開發者與實驗者。它不推斷一個人的感受或意圖。

<a id="first-experiment"></a>
## 首次實驗

依照[執行與驗證](#run-and-verify)啟動應用程式。先保持光線充足、臉部中性，依流程完成校準，再嘗試小幅、可見的動作，例如抬眉或張嘴。除了動作數值，也要觀察品質與不確定性指標。

清楚的正面視角與較困難的視角是有用的比較。低品質影格應視為有限證據，而非對臉部作出更強結論的依據。文件所述流程可降低推論權重或暫停推論。

這裡尚未嵌入真實攝影機錄影。隨附合成評估檢查的是測試契約，而不是對真人影片的準確度。

<a id="three-useful-things-to-compare"></a>
### 三項值得比較的內容

| 實驗 | 觀察內容 | 不應得出的結論 |
| --- | --- | --- |
| 保持臉部中性，再做小幅抬眉或嘴部動作 | 動作估計及其區間 | 某個數值衡量了情緒、真誠程度或意圖。 |
| 先用正面視角，再改為較困難的姿態或光線條件 | 品質分數、信心程度及暫停／降權行為 | 較差的影像提供了更強的個人證據。 |
| 明確開始一段短錄製，再匯出 | 本機歷史與 JSON/CSV 輸出 | 匯出結果是已驗證的診斷或真實環境準確度報告。 |

介面包含中英文切換、歷史記錄及 JSON/CSV 匯出控制項。錄製是主動操作，不是檢視即時處理流程的前提。

<a id="v311-algorithm-pipeline"></a>
## v3.11 演算法流程

1. MediaPipe 提供 468 個以上的正規化臉部關鍵點。
2. 影格品質門檻會評分關鍵點完整性、臉部邊界／尺度、頭部姿態、照明、對比、明暗截斷、清晰度，以及眼部區域可見性／眩光代理指標。
3. 影格會被放行、降低信心權重或暫停處理。暫停的影格不能更新 AU 推論或個人校準。
4. 穩健的個人基準使用中位數及中位數絕對偏差（MAD），拒絕低品質與離群影格，僅在靜止、高品質影格上施加緩慢且限幅的漂移更新。
5. AU 計算前，透過頭部姿態補償與按臉部尺度正規化的距離，減少姿態及穩定個體幾何特徵的影響。
6. 每個 AU 返回 `value`、`lower`、`upper`、`confidence` 及解剖區域 `region`。
7. 明確持續時間的貝氏時序濾波器取代按影格計數的遲滯機制，並報告後驗信心程度與正規化不確定性。
8. 從 AU 估計衍生十二種可觀察動作摘要，並傳遞相應區間。

專案未附帶訓練所得的模型。選用 AU 提供者的中繼資料必須包含名稱、版本、授權、訓練資料來源、AU 標籤對應與評估指標，才能啟用。其貢獻依品質加權且設有上限；確定性幾何規則仍作為備援方案。

<a id="run-and-verify"></a>
## 執行與驗證

準備 Node.js/npm、支援攝影機的現代瀏覽器，以及正常運作的攝影機。從儲存庫根目錄執行。攝影機存取使用 `localhost` 或 HTTPS，並允許連線載入 MediaPipe CDN 指令碼與網頁字型。本機影格處理不代表首次啟動完全離線。

```powershell
npm install
npm run check
npm start
```

`npm start` 在連接埠 8080 啟動靜態伺服器，並要求瀏覽器開啟。如有需要，請自行開啟 `http://localhost:8080`。此指令使用 `npx http-server`，首次使用可能下載伺服器。

**首次成功操作：**檢視即時校準／品質面板，做出一個可見動作，並將估計值與不確定性顯示比較。通過命令列檢查不能取代這項攝影機檢查。

`npm run check` 執行單元／契約測試、確定性 AU 指標測試資料、ESLint 及靜態發布檢查。評估 CLI 報告各 AU 的精確率、召回率、F1、偽陽性率，以及保留受試者的評估摘要：

```powershell
node scripts/evaluate-au.mjs evaluation/fixtures/synthetic-au-eval.json
```

隨附向量是合成契約測試，不是真實環境準確度的證據。固定影片清單的需求請見 [evaluation/README.md](../../evaluation/README.md)。v3.11 沒有可再散布且合法標註的真人影片資料集，因此本版不宣稱真實影片準確度或跨個體泛化能力。

<a id="main-modules"></a>
## 主要模組

- `face-quality.js` — 影格品質門檻與 AU 信賴區間
- `face-au-detector.js` — 穩健校準、姿態補償、確定性 AU 幾何計算
- `face-temporal.js` — 明確持續時間的貝氏狀態濾波器
- `face-observables.js` — 可直接觀察的動作摘要
- `face-model-adapter.js` — 受來源要求限制的選用分類器與規則備援
- `scripts/evaluate-au.mjs` — 固定清單 AU 指標與保留受試者報告

<a id="common-questions"></a>
## 常見問題

**這是情緒偵測器嗎？**不是。輸出是幾何與動作代理指標，不是心理狀態標籤。

**為什麼推論暫停或信心程度下降？**品質門檻考慮姿態、可見性、照明及其他影格條件。請檢查品質指標並改善畫面，不要將暫停結果解讀為對該人的負面發現。

**是否包含訓練所得的 AU 模型？**不包含。隨附流程使用確定性幾何方法。選用提供者需要中繼資料、來源、授權及評估資訊，才能參與計算。

**合成評估能證明在我的攝影機上的準確度嗎？**不能。它驗證指標／測試契約。真實影片驗證需要適當且合法標註的評估集，並遵循 [evaluation/README.md](../../evaluation/README.md) 的固定清單流程。

**錄製的歷史在哪裡？**開始錄製後，記錄保存在瀏覽器本機 IndexedDB。匯出是本機下載；即使不會自動上傳，也應將錄影與匯出檔視為個人資料。

<a id="privacy-and-limits"></a>
## 隱私與限制

攝影機影格在瀏覽器處理。本專案不會上傳任何內容。使用者開始錄製後才記錄歷史，並保存在本機 IndexedDB；匯出是明確觸發的本機下載。請勿將 FaceExpressionVFX 用於身分識別、監控、醫療保健、就業、保險、警務、教育懲戒或其他高影響決策。請參閱 [PRIVACY.md](../../PRIVACY.md)。

採用 MIT 授權。第三方函式庫及未來可能加入的資料集／模型保留各自授權。

<a id="help-improve-the-experiment"></a>
## 協助改進實驗

歡迎在結果可驗證的領域貢獻：

- 影格品質與校準的邊界案例。
- 無障礙標籤、更清楚的不確定性說明及翻譯改進。
- AU 幾何計算與時序行為的回歸測試。
- 使用適當授權且取得同意的資料，建置可重現的評估工具。

| 貢獻領域 | 建議從這些檔案入手 | 有用的證據 |
| --- | --- | --- |
| 影格品質邊界案例 | `face-quality.js`、`face-policies.js` | 聚焦的回歸案例，以及預期放行／降權／暫停行為。 |
| 校準或 AU 幾何計算 | `face-au-detector.js`、`face-temporal.js` | 確定性輸入序列與明確的預期輸出邊界。 |
| 語言與介面清晰度 | `face-i18n.js`、`index.html` | 兩種語言狀態，以及保留不確定性含義的說明。 |
| 評估工具 | `scripts/evaluate-au.mjs`、`evaluation/README.md` | 清單／綱要檢查；分別標註合成證據與真實影片證據。 |

從相關模組及 `npm run check` 開始。在 [pull request](https://github.com/son-gladyso/FaceExpressionVFX/pulls) 說明問題、證據、實際執行的測試及仍未驗證的部分。較大的變更請先在 [issue](https://github.com/son-gladyso/FaceExpressionVFX/issues) 討論，再著手實作。

若無相應分享權利與許可，請勿貢獻私人臉部錄影、生物辨識嵌入向量、模型權重或資料集。請保留可觀察動作，與關於身分、情緒、意圖或健康的主張之間的區別。
